# ASHA Changelog

## 1.7 --- Sex-Aware Personalization, Dynamic Persona & Interactive Multi-AI Wizard

### Added

-   **Dominant White & Orange Theme** (`#ffffff`, `#f97316`, `#ea580c`) with professional **Global Header & Footer** across all wizard steps.
-   **Top & Bottom Wizard Navigation Bars** on Steps 1–6 so users do not need to scroll back to the top after filling out form sections.
-   **Step 1/7 Nickname & Ethnicity**:
    -   Added `"What should I call you?"` (`nickname`) text input.
    -   Added `Ethnicity` (`Etnis`) dropdown with options: `Asian`, `Kaukasian`, `American`, `Latin`, `Indian`, `Other`.
    -   Sex selection states (`male`, `female`, `unspecified`) with Dynamic Persona background (`female_active`, `male_active`, `neutral`).
-   **Step 4/7 Staged Progressive Disclosure**:
    -   Stage 1: Primary Aspiration selection (`Build Muscle`, `Fat Loss`, `Weight Loss`, `Improve Mobility`, `Running Performance`, `Health Indicator`).
    -   Stage 2: Conditional sub-target inputs (`Muscle Mass %`, `Fat Percentage %`, `Target Weight Kg`, `Running Distance + Target Pace`, `Health Indicator + Target Value`).
    -   Stage 3: `Target Timeframe (Weeks)` revealed only after aspiration and sub-target are filled.
-   **Step 5/7 Three-Session Layout, Select All, Training Types & Equipment**:
    -   Organized Step 5/7 into 3 session blocks separated by 2 `<hr class="asha-session-divider" />` dividers.
    -   Added **Pilih Semua (Select All)** master checkbox for `Training Days` that automatically clears and disables (greys out) `Rest Days`.
    -   Added **Jenis Latihan (Training Types)** multiple-select checkboxes (`Cardio`, `Strength`, `Mobility & Flexibility`) before `Available Equipment`.
    -   Added `Tidak Ada (Gunakan Bodyweight)` and `Treadmil / Walking Pad` to `Available Equipment`.
    -   Added `<input type="time">` time picker for `Preferred Training Time`.
    -   Added conditional `IF Protocol` and `Eating Window` fields when `Intermittent Fasting` is selected.
-   **Step 6/7 Plan Start Date & Calendar Platform**:
    -   Added `Plan Start Date` (`<input type="date">` date picker).
    -   Added `Calendar Platform` selector (`Google`, `Outlook`, `Apple`).
-   **Step 7/7 Auto-Copy Clipboard, Personalized Motivational Popup & 5 AI Chat Launchers**:
    -   Replaced standard wizard navigation on Step 7/7 with **"Sebelumnya"** and **"Mulai Lagi"**.
    -   Removed on-screen Master Prompt display and extra post-statement buttons; checking the confirmation checkbox automatically copies the Master Prompt to the user's clipboard.
    -   Added a personalized Pop-Up Dialog (`role="dialog"`) displaying:
        `Selamat [nama_pengguna], prompt kamu sudah siap!`
        `Silakan klik AI Chat Interface favoritmu untuk membuat plan.`
        plus a randomly selected motivational quote.
    -   Added 5 clickable AI Chat Interface logo buttons: **ChatGPT**, **Gemini**, **Claude**, **Grok**, and **Copilot**.
-   **Master Prompt Enhancements**:
    -   Includes personal greeting instruction for `nickname`, selected `trainingTypes`, `planStartDate`, detailed **day-by-day** Training & Meal Plan across the full timeframe, a mandatory **Exercise Movement Guide** (`fungsi/manfaat gerakan`, `otot yang dilatih`, `repetisi`, `cara melakukan gerakan`, and `contoh/gambar gerakan` from `https://darebee.com`), and Generative AI `.ics` calendar generation inside the chat response.

### Changed

-   **Reordered Steps 2/7 and 3/7**: Client-Side Health Report OCR Upload is now **Step 2/7** (before **Step 3/7** Authoritative Health Snapshot) so extracted biomarkers pre-populate Step 3/7 for review.
-   `.ics` calendar files (`My Training Plan` and `My Diet Plan`) are now generated by the Generative AI in the chat response rather than static client-side buttons on Step 7/7.
-   Personal information model now explicitly includes `nickname`, `sex`, and `ethnicity`.
-   Schedule & equipment model now explicitly includes `trainingTypes` and `Treadmil / Walking Pad`.

### Safety / Privacy

-   Sex and ethnicity are not inferred.
-   Physiological states are not inferred; sensitive follow-up questions are conditional.
-   Runtime-only memory data handling remains strictly enforced (`no localStorage`, `no sessionStorage`, `no IndexedDB`, `no cookies`).
-   Visual personalization remains strictly decoupled from health recommendation logic.
